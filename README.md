# NOBEL · Заявки в Telegram

Учебный некоммерческий проект. Сайт работает на GitHub Pages, база и обработчики — в Supabase Free. Отдельный сервер не нужен.

## Что реализовано

- Форма → сохранённый черновик → одноразовая ссылка бота → подтверждение Start.
- Владелец: /requests, фильтры и страницы, карточка, история, ответ, статусы.
- Клиент: /my, только свои заявки, уточнения и ответы в том же боте.
- Ответ привязан к конкретной подсказке ForceReply. Два обращения одного клиента не смешиваются.
- Изменения сохраняются транзакционно. Повторные update_id и повтор формы не создают дублей.
- Исходящие сообщения хранятся в очереди. После ошибки можно выполнить /retry.
- Данные закрыты от anon/authenticated. Токен бота и серверный ключ отсутствуют на сайте.

## Состояние запуска

Исходники можно использовать без изменения логики, но настоящий приём обращений требует настройки своего бота и Supabase.
Пока public/config.js пуст, кнопка отправки отключена и сайт честно сообщает, что приём не подключён.
Публикация страницы сама по себе не означает работу бота.

## Локальная проверка

Нужен Node.js 22.

```text
npm ci
npm test
npm run check
npm run preview
```

Откройте адрес, выведенный preview. Тесты запускают настоящий PostgreSQL-движок PGlite, применяют SQL и проверяют обмен двух клиентов с владельцем. Telegram в этих тестах заменён тестовым транспортом: живую доставку нужно проверить отдельно.

## Подключение: короткий порядок

1. Через @BotFather создайте отдельного нового бота, затем нажмите Start в нём.
2. Создайте проект Supabase Free. Выполните по порядку оба SQL из supabase/migrations. Они создают отдельную схему requests_app, не удаляя чужие таблицы.
3. Добавьте Secrets: BOT_TOKEN, BOT_USERNAME без @, TG_WEBHOOK_SECRET, SETUP_SECRET, FORM_SECRET, SITE_URL. Последние три секрета — разные случайные строки длиной от 32 символов. ADMIN_CHAT_ID пока можно не задавать.
4. Запустите `npm run bundle`. В .local/dashboard появятся три самостоятельных файла для редактора Supabase. Создайте функции create-application, telegram-hook, setup-telegram. Для каждой отключите Verify JWT: авторизация telegram-hook и setup-telegram выполняется внутри кода.
5. Для доступа к базе функции используют стандартные серверные SUPABASE_URL и SUPABASE_SERVICE_ROLE_KEY. При необходимости добавьте серверный ключ в SERVER_DB_KEY. Эти значения не публикуют в GitHub.
6. В Test функции setup-telegram отправьте POST, заголовок X-Setup-Secret: ваш SETUP_SECRET, тело {"action":"register"}. Затем {"action":"status"} — проверьте username и URL. Запрос к Telegram API отправляет Supabase, не ваш ПК.
7. В личном чате бота отправьте /id. В Secrets добавьте полученное число как ADMIN_CHAT_ID. Проверьте /requests.
8. В Test setup-telegram выполните {"action":"test"}. Удалите временную setup-telegram после проверки.
9. В public/config.js вставьте URL create-application и BOT_USERNAME. В SITE_URL должен быть точный полный адрес сайта; CORS origin выводится из него автоматически.
10. Опубликуйте изменения. Пройдите полный путь с другим Telegram-аккаунтом.

Настройка принимает обращения только после задания ADMIN_CHAT_ID. База автоматически удаляет неподтверждённые черновики старше суток при поступлении новых форм. Код привязки действует 30 минут.

Остальные исходники открыты для изучения, секреты хранятся только в Supabase и игнорируемой папке .local/.
Не записывайте настоящие токены в примеры, issues, историю Git и сообщения чата.

## Реальное время и ограничения

События доставляются Telegram webhook сразу, без опроса по расписанию. Точное время зависит от сети и сервисов.
У бесплатного Supabase есть квоты и возможность паузы при низкой активности за неделю.
GitHub Pages имеет ограничения на коммерческое использование. Этот проект предназначен для обучения и некоммерческих обращений.

Обычные повторы входящих событий не дублируют ответ. При аварии ровно между успешной отправкой в Telegram и фиксацией результата в базе повторная доставка теоретически может продублировать сообщение: Telegram sendMessage не предоставляет ключ идемпотентности.

## Приёмка перед реальным использованием

- Два разных клиента и владелец.
- Повтор отправки формы и повтор Start.
- Два обращения одного клиента и ответы по ним в обратном порядке.
- Попытка открыть чужую карточку и назначить чужой статус.
- Получение ответа и уточнение клиента.
- Блокировка бота, сохранение ошибки, разблокировка и /retry.
- Сохранение истории после закрытия браузера и при выключенном компьютере владельца.

## Структура

public/ — страница без сборки  
supabase/migrations/ — закрытые таблицы, атомарные операции и очередь  
supabase/functions/ — общий обработчик и три точки входа  
tests/ — проверки PostgreSQL, прав и HTTP  
scripts/ — локальный просмотр, проверка и сборка файлов для панели  

Вложения и голосовые сообщения пока не поддерживаются. Переписка текстовая, до 2000 символов на сообщение.
